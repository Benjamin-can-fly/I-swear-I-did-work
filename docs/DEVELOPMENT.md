# 工作日志

本机运行的工作记录、待办事项、时间线和数据后台。双击桌面的“工作日志”，或运行 `启动工作日志.cmd`，打开 http://127.0.0.1:4317 。

## 当前使用方式

- 两个页面使用相同的页面内输入区，直接填写、上传附件并保存，不再弹出确认窗口。`Enter` 保存，`Ctrl + Enter` 换行（Mac 也支持 `Command + Enter` 换行）；输入法选字时不触发保存。
- 正文自动长高，到上限后框内滚动。项目、耗时、投入程度、重点标记、任务状态和关联记录在“更多选项”中。展开后整页可以滚动；窄窗口自动换行，保存按钮不再被输入区高度限制裁掉。
- AI 整理、总结和本地精简已下架，相关接口返回 410。当前不发送内容到模型，也不加载本地模型。旧记录原文及已有字段保留在数据中。
- 图片以保持比例的小方形预览显示；PDF、Word、Excel、PPT 等文件使用带类型标识的小卡片。点击预览打开原图，点击文件下载原文件。
- 每个附件上限 20 MB，每条内容最多 50 个附件。图片预览最长边 240 像素，原始文件保持不变。附件存放在 `data/attachments/`。
- 每条日记录和待办右侧的三点菜单提供修改、删除等操作。修改回到页面输入区；删除可在 15 秒内撤销。已完成或搁置的任务可返回待处理。
- 新任务创建时自动记录开始时间，可手动修改。标记完成时自动记录实际完成时间；开启“自动同步至工作记录”后，在同一次保存中生成工作记录，包含任务内容、附件及开始和完成时间；重复操作不重复生成记录。
- 单击任务文字或圆角勾选框可完成任务。鼠标或可按下的触摸板可在任务文字区域按住横划，划线达到阈值后松开完成；短距离或明显纵向移动取消。修改从三点菜单进入。
- 返回待处理会清除这次完成时间，并删除对应自动工作记录，包括手动修改后的版本；撤销状态操作会恢复对应记录。旧任务没有完成时间时不补造历史记录。
- 两页均支持把图片、文档拖到输入区。上传后自动存入草稿，刷新仍可恢复；保存记录或待办后，附件随条目进入时间线。
- 待办分类依次为“待处理、已搁置、已完成”。下方日期工具栏与右侧汇总的位置和工作记录一致，汇总按截止日期统计所选时段的任务数量及状态。

## 日期与统计

日期检索按钮提供两种视图：Type one 按天或按周列出事件，可横排或竖排；Type two 使用月历网格。AI 下架后，事件内容采用已保存文字的摘录，不自动生成总结。

两页新建时的日期默认今天，时间默认当前分钟；旧草稿中的空白值会补齐。输入区日期两侧的箭头每次前后调整一天；日期后显示星期，选择星期会切换到当前所选日期所在周的对应日期。未手动调整的新增日期时间在保存时使用当前分钟。

时间右侧“应用”为开关。开启时使用填写的日期及分钟；关闭时待办不设截止时间，工作记录按实际保存时间记录。

工作记录的日查看当日；周按当前月份分周回顾；月按全年 12 个月查看手动标记的重点。待办的日、周、月按截止日期筛选当天、所在周或所在月，也可以选择“全部日期”。

独立的“时间线”页面将工作记录与待办按日期合并展示，可按月份检索、横向或纵向查看。完成事项按实际完成日期显示，未来安排按截止日期显示；逾期未完成的事项仍标为待办。由完成待办生成的工作记录在时间线上只显示一次。未设置日期或缺少历史完成时间的任务单独列出。

任务正文与执行时间分列显示，右侧列出开始、完成时间和截止状态。跨天的提前或逾期时长显示天和小时，具体时间保留到分钟。后台超时率和提前率以所选时段内已完成、并有截止日期和完成时间的任务为分母；不把仍未完成的任务混入分母。仅设截止日期时按当天 23:59 计算。旧任务没有完成时间时显示未记录，不补造历史时间。

## 数据和备份

- 正式记录：`data/journal.json`；上一次成功保存前的数据：`data/journal.previous.json`。
- 输入草稿：当前浏览器本地存储，包括已上传附件的引用。保存失败保留输入。
- JSON 备份包含记录、待办及这些条目引用的原始附件。导入时合并新编号，已有同编号内容不覆盖；附件重新保存到本机。
- JSON 备份导入上限 200 MB。更多附件建议直接备份整个 `data` 文件夹。Markdown 是文字导出，不是附件备份。
- 移除附件或删除条目不会立刻删除磁盘上的原文件，以支持撤销和旧备份恢复。
- 单机单用户运行，绑定本机地址。手机尺寸是响应式界面，当前没有账号同步或公网访问。

## 开发与验证

需要 Node.js 22.9+；当前机器已安装 Node.js。日常运行无额外依赖。开发先执行 `npm ci`。

- `npm start`：启动。
- `npm test`：日期、数据兼容、截止时长和比例等核心检查。历史整理器测试仅用于保留代码的回归，并不代表该功能仍开放。
- `npm run test:ui`：在独立临时数据和端口 4318 上使用 Edge 检查页面内保存、附件、菜单、日期视图、失败恢复、统计、动画和桌面/手机布局。
- `node tests/timeline-ui.mjs`：检查两页布局对齐、截止日期与星期联动、跨年调整、完成待办同步记录、撤销、独立时间线及四页窄屏导航。
- `node tests/keyboard.mjs`：检查两个输入区的 Enter 保存、Ctrl + Enter 换行和输入法选字保护。
- `node tests/usability-ui.mjs`：检查旧空白草稿修复、分钟默认值、“应用”开关、拖入附件与恢复、文字 / 方框 / 横划完成、重复点击、修改过的记录同步撤回、失败保存及 320 至 900 像素小窗口滚动。

界面截图保存在 `artifacts/`，其中的数据均为测试样例。

完整图文使用说明：`output/pdf/工作日志使用说明.pdf`，含 14 页界面、按钮和常见操作说明。


## 桌面预览版与汇报导出（0.2.2）

Windows x64 桌面版使用 WinForms / WebView2 与随包 Node.js。朋友只需安装 dist/WorkLog-0.2.2-windows-x64-setup.exe，无需开发环境。安装时使用共享 WebView2；缺少时提示联网安装。名称为 Work Log，内置统一图标与可选配色，安装包未做代码签名。

桌面数据保存到 `%LOCALAPPDATA%\WorkJournal\data`，与原版项目 `data` 分开。旧版导出 JSON 后在桌面版导入即可迁移。安装包不含私人数据。升级/卸载保留用户数据，不会自动迁移浏览器草稿。

待办的“自动同步至工作记录”新建默认关闭；旧任务未设置标志时保留原同步行为。开启后，完成、修改、回退、搁置、删除会单向同步到自动记录；关闭会撤回该记录。工作记录的新建、修改、删除不改变待办。后续主动保存待办时会重新同步正文等共享字段，记录中的耗时、投入程度与重点保留。只依据 sourceTaskId 关联，普通 recordId 关联不参与级联删除。

时间线 → “选择事项 · 导出汇报”：逐条、按日、按周、按月勾选；分组和全选只作用于当前筛选下可见事项，跨月份保留已选内容。自定义标题后导出 PDF。桌面版直接选择保存位置；浏览器版在预览中打印并选择另存为 PDF。完整正文不截断，附件列出名称而不嵌入；已完成任务与自动记录只出现一次。不提供自动改写或 AI 总结。

### 在另一台 Windows 开发机构建

需要 Windows x64、.NET Framework 4.7.2+（本机使用系统 csc）、Node.js 22.9+。Windows 10/11 自带 tar 用于解包 NSIS。构建目录不要混入私人文件。

1. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-desktop.ps1`：下载校验 WebView2 SDK、NSIS 和 Microsoft 运行时引导安装器；下载当前 Node 版本许可证。
2. 确保 `output/pdf/工作日志使用说明.pdf` 存在。需要重生成时运行 `scripts/create-guide.py`（需 ReportLab、Pillow 和微软雅黑字体，截图由 UI 测试生成）。
3. `npm run build:desktop`：编译桌面外壳，按白名单拷贝运行文件，生成安装包及 SHA-256。Node 使用开发机当前安装版本，正式发布应固定版本。`-StageOnly` 可仅生成运行目录。
4. 将安装包、校验文件和使用说明放到 GitHub Releases。教程位于 `output/pdf/分享软件与上传GitHub教程.pdf`。

新增验证：`node tests/report-ui.mjs` 覆盖跨月批选、分组、取消勾选、无数据变更、中文长文 PDF 与窄屏。`tests/desktop-smoke.js` 在独立临时数据目录内验证原生窗口保存、桥接和直接 PDF 导出。测试端口与正式使用端口分离。
